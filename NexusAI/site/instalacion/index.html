Guía de instalación

Instalar NexusAI paso a paso.

NexusAI tiene dos partes: el plugin, que se instala en Moodle, y un servidor propio que busca en el material y habla con la IA. Esta guía instala las dos, las conecta y deja el asistente listo para usar en los cursos.

Antes de empezar

Vas a necesitar:

  • Moodle 4.5 a 5.3, con una cuenta de administrador del sitio.
  • Una máquina Linux para el servidor de NexusAI, con acceso a internet. Puede ser la misma de Moodle u otra.
  • Una clave de un proveedor de IA compatible con la API de OpenAI. Gemini tiene una capa gratuita: la clave se saca en Google AI Studio.
  • Si Moodle va a llegar al servidor por internet: un dominio o subdominio que apunte a esa máquina.

El único que se conecta con el servidor de NexusAI es el servidor de Moodle. Los navegadores de los alumnos nunca le hablan directo, así que no hace falta publicarlo para todo el mundo.

1Instalar el servidor

El servidor corre en Docker con una imagen ya armada, así que no hay que compilar nada. Son cuatro contenedores: la API de NexusAI, PostgreSQL con pgvector (la base de datos y el índice del material), Redis y, si usás HTTPS, Caddy. Todo sale del repositorio nexusai-backend.

1.1 La máquina

  • Sistema: Linux. Los comandos de esta guía son para Ubuntu o Debian.
  • Memoria: alcanza con una máquina chica. Nuestros servidores tienen 1 GB de RAM.
  • Disco: la primera vez se descargan unos 1,5 GB de imágenes. Después crece con el material que suban los docentes (hasta 20 MB por archivo).
  • Red: salida a internet, para hablar con el proveedor de IA. Si usás HTTPS, además los puertos 80 y 443 abiertos hacia esa máquina; en una nube, abrilos también en las reglas de red del proveedor.

1.2 Instalar Docker

Si la máquina no tiene Docker, el script oficial instala Docker y Docker Compose:

curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker $USER

El segundo comando te deja usar docker sin sudo. Cerrá la sesión y volvé a entrar para que tome efecto. Para comprobarlo:

docker compose version

Tiene que mostrar una versión 2 o posterior.

1.3 Descargar los archivos

git clone https://github.com/nexusai-ucc/nexusai-backend.git
cd nexusai-backend
cp .env.example .env

De acá en adelante, todos los comandos se corren dentro de la carpeta nexusai-backend. El archivo que levanta todo es docker-compose.selfhost.yml, y .env ya lo deja elegido, así que alcanza con escribir docker compose.

1.4 Configurar .env

Primero generá dos valores al azar: uno para la API key y otro para el secreto compartido. Corré este comando dos veces y copiá cada resultado:

openssl rand -hex 32

Después abrí .env (por ejemplo con nano .env) y reemplazá los valores de ejemplo. Queda algo así:

COMPOSE_FILE=docker-compose.selfhost.yml
ENV=production

LLM_API_KEY=AIzaSy...tu-clave-de-gemini
EMBEDDING_API_KEY=AIzaSy...tu-clave-de-gemini

NEXUSAI_API_KEY=3f9c1e...el-primer-valor-de-openssl
NEXUSAI_SHARED_SECRET=a71e0b...el-segundo-valor-de-openssl

POSTGRES_USER=nexusai
POSTGRES_PASSWORD=una-contraseña-larga-cualquiera

API_PORT=8001
VariableQué es
LLM_API_KEYLa clave del proveedor de IA que responde las preguntas.
EMBEDDING_API_KEYLa clave con la que se indexa el material. Con Gemini, la misma que la anterior.
NEXUSAI_API_KEYEl primer valor generado. Va también en Moodle, en el paso 3.
NEXUSAI_SHARED_SECRETEl segundo valor generado. También va en Moodle.
POSTGRES_PASSWORDLa contraseña de la base de datos. Se usa solo adentro de Docker, así que puede ser cualquiera.
API_PORTEl puerto de la máquina donde queda la API. Cambialo si el 8001 ya está ocupado.

No cambies POSTGRES_PASSWORD después del primer arranque. La base se crea con esa contraseña: si la cambiás en .env, la API ya no puede conectarse.

1.5 Elegir cómo llega Moodle

Depende de dónde esté Moodle:

  • Misma máquina o misma red interna. No hace falta nada más. En el paso 3, la URL del servidor es http://IP-de-la-maquina:8001, o http://localhost:8001 si es la misma máquina.
  • Por internet. Usá HTTPS, para que las preguntas y el material viajen cifrados. Creá un registro DNS tipo A que apunte tu dominio (por ejemplo nexusai.tu-institucion.edu) a la IP pública de la máquina, y agregá al final de .env:
COMPOSE_PROFILES=https
NEXUSAI_DOMAIN=nexusai.tu-institucion.edu
API_BIND=127.0.0.1

COMPOSE_PROFILES=https suma Caddy, que pide y renueva solo el certificado HTTPS. API_BIND=127.0.0.1 deja el puerto 8001 cerrado hacia afuera, para que solo se entre por HTTPS. En el paso 3, la URL del servidor es https://nexusai.tu-institucion.edu.

¿Querés probar sin dominio propio? nip.io arma uno con la IP: NEXUSAI_DOMAIN=nexusai.203.0.113.10.nip.io (cambiá los números por la IP pública de la máquina). Sirve para pruebas, no para uso real. Si la institución ya tiene un proxy (nginx, Apache), no uses Caddy: dejá API_BIND=127.0.0.1 y apuntá el proxy a http://127.0.0.1:8001.

1.6 Levantar y comprobar

docker compose up -d

La primera vez descarga las imágenes y crea la base de datos, así que tarda unos minutos; después arranca en segundos. Para ver el estado:

docker compose ps

api, postgres y redis tienen que figurar Up y (healthy), y caddy Up si usás HTTPS. uploads-init figura terminado: es normal, solo prepara la carpeta del material y se cierra. Probá la API:

curl http://localhost:8001/health

Con HTTPS, probala también desde afuera: curl https://nexusai.tu-institucion.edu/health. Tiene que responder algo como:

{"status":"ok","version":"0.1.0","env":"production","llm_model":"gemini-3.5-flash"}

Si no responde, mirá el registro con docker compose logs api y buscá el caso en Problemas comunes.

1.7 Mantenerlo

Ver qué está pasando. El registro de la API, en vivo (salís con Ctrl+C):

docker compose logs -f api

Actualizar a la última versión. Los cambios en la base de datos se aplican solos al arrancar:

git pull
docker compose pull
docker compose up -d

Hacer una copia de seguridad. La base de datos y los archivos originales del material:

docker compose exec -T postgres pg_dump -U nexusai nexusai > nexusai-$(date +%F).sql
docker compose cp api:/app/uploads ./uploads-$(date +%F)

Guardá esas copias fuera de la máquina. Para programarlas, agregalas a crontab -e.

Restaurar una copia. Esto reemplaza la base actual por la de la copia (cambiá el nombre del archivo):

docker compose stop api
docker compose exec -T postgres dropdb -U nexusai nexusai
docker compose exec -T postgres createdb -U nexusai nexusai
docker compose exec -T postgres psql -U nexusai nexusai < nexusai-2026-11-26.sql
docker compose cp ./uploads-2026-11-26/. api:/app/uploads
docker compose up -d

Apagarlo. docker compose down apaga todo y conserva los datos. Con docker compose up -d vuelve a arrancar.

No uses docker compose down -v salvo que quieras borrar todo: la -v elimina la base de datos y el material.

2Instalar el plugin

  1. Descargá el .zip desde el Marketplace de Moodle.
  2. En Moodle, entrá a Administración del sitio → Extensiones → Instalar plugins.
  3. Subí el archivo y seguí el instalador hasta el final.

Si tu Moodle no permite instalar desde la web, descomprimí el .zip en local/nexusai (en Moodle 5.1 o posterior, public/local/nexusai) y entrá a Administración del sitio → Notificaciones.

3Conectar los dos

En Administración del sitio → Extensiones → Extensiones locales → Configuración de NexusAI, sección Conexión con el backend:

CampoValor
URL del backendLa que elegiste en el paso 1.5: https://nexusai.tu-institucion.edu o http://IP-de-la-maquina:8001
API keyEl valor de NEXUSAI_API_KEY
Shared secret (HMAC)El valor de NEXUSAI_SHARED_SECRET

Guardá los cambios y purgá las cachés en Administración del sitio → Desarrollo → Purgar todas las cachés.

Cuidá las dos claves. Con ellas se le puede pedir cualquier cosa al servidor en nombre de cualquier usuario. No las mandes por correo ni las subas a un repositorio.

4Verificar la conexión

Abrí Extensiones locales → NexusAI · Panel de administración (o la dirección /local/nexusai/admin.php de tu Moodle). El panel consulta al servidor y muestra si responde, su versión y cuánto tarda.

Si muestra un error, buscá el caso en Problemas comunes.

5Activar NexusAI en los cursos

NexusAI viene apagado en todos los cursos, para poder activarlo de a uno. Hay tres formas:

  • El docente, desde su curso. En el menú del curso (a veces dentro de «Más») abre NexusAI en este curso, marca Usar NexusAI en este curso y guarda. Pueden hacerlo los profesores con permiso de edición y los gestores.
  • En todos los cursos a la vez. En Configuración de NexusAI, marcá Activado por defecto en los cursos. Vale para los cursos que no tengan su propia configuración.
  • Por consola, desde la carpeta de Moodle:
php local/nexusai/cli/enable_course.php --courseid=12
php local/nexusai/cli/enable_course.php --list   # en qué cursos está activado

Con el curso activado, el docente sube su material y los alumnos ya pueden usarlo. Cómo se hace está en el tutorial.

En Moodle

Están en la misma página, Configuración de NexusAI:

AjustePara qué sirveDe fábrica
Límites de tokensCuánto puede usar cada rol por hora y por día. Los alumnos ven cuánto les queda.Con límites
Mostrar fuera de un cursoMuestra el asistente también en las páginas que no son de un curso.Apagado
Los usuarios pueden cargar su propia API keyCada usuario puede cargar la clave de su propia cuenta de IA. Se usa solo cuando se agota la cuota de la institución, y en ese caso la pregunta y los fragmentos del material van a su proveedor. Desde la versión 0.20.0.Apagado

En el servidor

Se agregan al .env del servidor. Después de cambiarlo, aplicalo con docker compose up -d --force-recreate api.

Para quéVariables
Usar otro proveedor de IA para responderLLM_BASE_URL, LLM_MODEL y LLM_API_KEY. Por ejemplo, para OpenAI: LLM_BASE_URL=https://api.openai.com/v1 y LLM_MODEL=gpt-4o-mini. El material puede seguir indexándose con Gemini.
Recibir alertas por correo (errores, IA caída o lenta)ALERT_SMTP_HOST, ALERT_SMTP_PORT, ALERT_SMTP_USER, ALERT_SMTP_PASSWORD y ALERT_EMAIL_TO. Hacen falta las tres: el usuario y la contraseña SMTP, y ALERT_EMAIL_TO con la dirección que las recibe. Sin alguna de ellas no se manda nada.
Límite de preguntas por usuarioRATE_LIMIT_PER_USER_DAILY (50 por día de fábrica) y RATE_LIMIT_PER_USER_MINUTE (20 por minuto).

Problemas comunes

El panel de administración no se puede conectar con el servidor

El servidor de Moodle no llega al de NexusAI. Desde el servidor de Moodle, probá curl con la URL que cargaste más /health. Si no responde, revisá que el dominio apunte a la máquina correcta y que ningún firewall corte el puerto (443 con HTTPS, 8001 sin HTTPS). Si la salida a internet pasa por un proxy, cargalo en Administración del sitio → Servidor → HTTP.

Error de autenticación (401)

La API key o el secreto compartido de Moodle no coinciden con los del .env: revisá que no se haya pegado un espacio de más. También pasa si los relojes de los dos servidores difieren en más de 5 minutos: activá la sincronización horaria (NTP) en ambos.

El asistente no aparece en el curso

Revisá que NexusAI esté activado en ese curso (paso 5) y que Activar NexusAI esté marcado en la configuración. Después purgá las cachés. El usuario también necesita el permiso local/nexusai:use, que alumnos y profesores tienen de fábrica.

Responde que no encuentra la información en el material

El archivo puede no haber terminado de indexarse: en NexusAI · Material tiene que figurar como indexado. NexusAI además solo responde con el material que cada alumno puede ver: si la actividad está oculta o restringida, para ese alumno no existe.

La API no arranca o se reinicia sola

Mirá el registro con docker compose logs api. Las causas más comunes: quedó un valor de ejemplo en .env (REPLACE_ME); se cambió POSTGRES_PASSWORD después del primer arranque; o API_PORT no es un número (la dirección va en API_BIND). Si el error dice port is already allocated, el puerto está ocupado: cambiá API_PORT.

Caddy no consigue el certificado HTTPS

Mirá docker compose logs caddy. Para pedir el certificado, el dominio tiene que apuntar ya a la IP pública de la máquina (un registro DNS nuevo puede tardar en propagarse) y los puertos 80 y 443 tienen que estar abiertos, también en las reglas de red de la nube. Caddy reintenta solo.

El chat responde con un error

Suele ser el proveedor de IA: la clave es incorrecta o se terminó la cuota. La capa gratuita de Gemini tiene un límite diario de pedidos. El detalle aparece en docker compose logs api.
